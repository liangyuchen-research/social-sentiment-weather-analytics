# Infrastructure setup

These manifests describe the original Melbourne Research Cloud deployment: one Kubernetes control-plane node, three workers, Elasticsearch and Kibana 9.2.4, and Fission 1.22.0. They are configuration examples for an authorized cluster, not credentials for a running service.

## Kubernetes and storage

Use the OpenStack client and project credentials supplied by your cloud administrator. Select a cluster template and machine flavor available to your project:

```bash
openstack coe cluster template list
openstack flavor list
```

For a new project cluster, set the appropriate values in your shell before provisioning:

```bash
openstack coe cluster create sentiment-weather \
  --cluster-template "$CLUSTER_TEMPLATE" \
  --master-count 1 --node-count 3 \
  --master-flavor "$MASTER_FLAVOR" --flavor "$WORKER_FLAVOR"
openstack coe cluster config sentiment-weather --dir ./cluster-config
export KUBECONFIG="$PWD/cluster-config/config"
kubectl get nodes
```

The supplied `storage-class.yaml` uses the MRC Cinder driver and `melbourne-qh2-uom` availability zone. Adapt it for another provider. The retain policy preserves volumes after a workload is removed.

```bash
kubectl apply -f installation/storage-class.yaml
```

## Elasticsearch and Kibana

```bash
helm repo add elastic https://helm.elastic.co
helm repo update
helm upgrade --install elastic-operator elastic/eck-operator \
  --namespace elastic --create-namespace --version 3.2.0
kubectl apply -f installation/elasticsearch.yaml
kubectl apply -f installation/kibana.yaml
kubectl get pods -n elastic
```

Keep the credentials generated by the operator. For local access, export the public CA certificate and forward the service:

```bash
mkdir -p config
kubectl -n elastic get secret elasticsearch-es-http-certs-public \
  -o jsonpath='{.data.ca\.crt}' | base64 --decode > config/elasticsearch-ca.crt
kubectl port-forward -n elastic service/elasticsearch-es-http 9200:9200
```

In another terminal, retrieve the operator-generated password and set it in your private `.env` file:

```bash
kubectl -n elastic get secret elasticsearch-es-elastic-user \
  -o jsonpath='{.data.elastic}' | base64 --decode
```

Use `ES_HOST=https://localhost:9200`, `ES_VERIFY_CERTS=true`, and `ES_CA_CERT=config/elasticsearch-ca.crt`. For a forwarded connection, set `ES_TLS_SERVER_NAME=elasticsearch-es-http.elastic.svc` if that service name appears in the certificate. This keeps hostname verification aligned with the service certificate while the TCP connection uses localhost.

```bash
python database/es_client.py
python database/setup_indices.py
python database/bulk_upload.py --all
```

The Python Elasticsearch 8.19 client uses the server's compatibility API. Live service compatibility still needs verification in the target deployment.

## Fission

Install the Fission CLI matching the deployment version using its [official release](https://github.com/fission/fission/releases/tag/v1.22.0).

```bash
export FISSION_VERSION=1.22.0
kubectl create -k "github.com/fission/fission/crds/v1?ref=v${FISSION_VERSION}"
helm repo add fission-charts https://fission.github.io/fission-charts/
helm repo update
helm upgrade --install fission fission-charts/fission-all \
  --version "v${FISSION_VERSION}" --namespace fission --create-namespace \
  --set routerServiceType=ClusterIP --set persistence.storageClass=perfretain
fission check
```

Continue with the [function packaging and deployment guide](../backend/fission/README.md). It covers the separate Python runtime, Elasticsearch certificate secret, social API configuration, and route/timer specifications.

The supplied manifests and package contents are checked offline. This public release has not provisioned a new cluster or repeated the original live cloud deployment.
